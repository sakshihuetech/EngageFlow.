# MongoDB data model

Source of truth: `backend/src/models/*.ts`. The 15 Mongoose models below map to the indicated default MongoDB collection names. ObjectId references are logical relationships, not relational foreign keys. Indexes listed here are **schema declarations**; `backend/src/config/database.ts` sets `autoIndex:false` and `autoCreate:false`, so actual live indexes and existing data compatibility are **not verified**. Do not run `syncIndexes`, drop indexes, or migrate live data without a separate reviewed rollout.

| Model → collection (source file) | Important fields, scope and relationships | Declared uniqueness / lifecycle and writers |
| --- | --- | --- |
| `Workspace` → `workspaces` (`workspace.model.ts`) | `name`, `slug`, `status`; root tenant ObjectId. | Unique slug; workspace administration/legacy data. No user authentication model. |
| `MetaConnection` → `metaconnections` (`meta-connection.model.ts`) | `workspaceId`, provider, business identifiers, onboarding mode, status, webhook/sync state. | Workspace+provider unique; Setup onboarding/refresh/disconnect updates; historical connection retained. |
| `MetaCredential` → `metacredentials` (`meta-credential.model.ts`) | `workspaceId`, `connectionId`, encrypted access token, expiry/scopes. | Workspace+connection unique; Setup writes. Token is server-only/hidden by query selection. |
| `WhatsAppAccount` → `whatsappaccounts` (`whatsapp-account.model.ts`) | `workspaceId`, `connectionId`, `wabaId`, status. | Workspace+WABA unique; Setup sync/onboarding writes. Sender-bound features reference account ID. |
| `WhatsAppPhoneNumber` → `whatsappphonenumbers` (`whatsapp-phone-number.model.ts`) | `workspaceId`, `accountId`, Meta `phoneNumberId`, registration/code/name status, last sync. | Workspace+account+phone unique; Setup refresh marks missing phones unavailable, retaining historical row. |
| `WhatsAppTemplate` → `whatsapptemplates` (`whatsapp-template.model.ts`) | `workspaceId`, `accountId`, Meta template ID, name/language/category, components/status/source. | Workspace+account+Meta ID unique; authoring/Meta sync updates; `deletedAt`/`isActive` support soft deletion. |
| `Contact` → `contacts` (`contact.model.ts`) | `workspaceId`, phone, status, embedded tags/attributes, account-scoped `whatsappConsent` status/source/evidence. | Workspace+phone unique; Audience/import/consent edits. `DELETED` status is retained rather than physical deletion in normal flow. |
| `Segment` → `segments` (`segment.model.ts`) | `workspaceId`, name, STATIC/DYNAMIC type, definition, count, status. | Workspace+name unique; Audience writes; `ARCHIVED` is retained. No separate Tag model. |
| `Campaign` → `campaigns` (`campaign.model.ts`) | `workspaceId`, account/phone/template binding, audience and mapping snapshot, schedule, status/counters. | Workspace-scoped campaign lookup; idempotency/launch partial unique indexes; Broadcast create/edit/launch/worker/webhook update. |
| `CampaignRecipient` → `campaignrecipients` (`campaign-recipient.model.ts`) | `workspaceId`, campaign/contact, recipient key, phone/template snapshot, status, retry attempts/failure metadata/message IDs. | Workspace+campaign+recipient key unique; launch snapshots, worker/retry/webhook updates; history retained. |
| `WhatsAppMessage` → `whatsappmessages` (`whatsapp-message.model.ts`) | `workspaceId`, account/phone, provider `metaMessageId`, direction/status/source; campaign recipient, API execution and conversation correlations. | Provider message ID unique; declared sparse correlation indexes need live compatibility review for multiple API attempts. Test send, workers and webhooks write. |
| `Conversation` → `conversations` (`conversation.model.ts`) | `workspaceId`, account/phone+customer, last message, status, unread, `assignedTo` ObjectId. | Workspace+account+phone+customer unique; inbound webhook/Inbox writes. Assignment field alone is not RBAC. |
| `ApiCampaign` → `apicampaigns` (`api-campaign.model.ts`) | `workspaceId`, stable slug, account/phone/template binding, variable schema, status and sender-change history. | Workspace+slug unique; Developer UI lifecycle. Archived records retained. |
| `ApiCampaignExecution` → `apicampaignexecutions` (`api-campaign-execution.model.ts`) | `workspaceId`, campaign/credential/contact, idempotency key, status, retry state/history, failure and webhook timestamps. | Workspace+campaign+idempotency key unique; trigger, worker, retry and webhook update. History retained. |
| `ApiCredential` → `apicredentials` (`api-credential.model.ts`) | `workspaceId`, key prefix, hidden SHA-256 `secretHash`, status. | Key prefix globally unique; create/rotate/revoke. Plaintext key returned only at creation/rotation, not stored. |

## Relationships and retention

Workspace is the top-level scope; account and phone IDs further bind sender-specific templates, campaigns, messages, conversations and consent. A disconnected WABA or unavailable phone must remain in historical records but must not become a new sender merely because another account is connected. Recipients and API executions preserve attempt evidence; do not delete old messages while reconciling webhooks. Most models use Mongoose timestamps. There is no general retention/TTL policy visible across these business collections: plan one explicitly before production use.

## Index rollout warning

Read [`docs/features/api-campaigns.md`](features/api-campaigns.md) and [`docs/features/broadcast-campaigns.md`](features/broadcast-campaigns.md) before changing retry indexes. A schema-declared compound sparse index involving `workspaceId` and an optional correlation field can behave differently from an intended partial index, and existing installed indexes are unknown. Inventory `getIndexes()` on a **read-only authorized environment**, compare against expected multi-attempt writes, then propose a backward-compatible migration for separate approval. No automatic index reconciliation should be added to startup.
