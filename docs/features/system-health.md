# System Health

The existing System Health page and `GET /api/health/ready` report MongoDB, Redis, Broadcast queue/worker and API Campaign queue/worker. Queue cards show waiting/active/delayed/failed aggregate counts, never job payloads or contact details. Counts are finite, nonnegative bounded integers. Provider transport configuration is independent of queue/worker health.

Both existing worker entrypoints publish lightweight Redis leases every 15 seconds under `engageflow:worker:broadcast:heartbeat` and `engageflow:worker:api-campaign:heartbeat`. Payloads contain only a random process-instance identity and timestamp; no workspace, phone, credentials, jobs or MongoDB writes. Each lease has a 120-second TTL. A timestamp at most 45 seconds old is HEALTHY; an existing older lease is STALE; missing/expired/malformed/future/unreadable leases are NOT_VERIFIED. After expiry, a previously stale worker becomes NOT_VERIFIED, not healthy.

Heartbeat writes do not overlap; outages cannot create a periodic unbounded write backlog. Graceful shutdown clears the timer and conditionally removes only this instance's lease, then closes the queue before disconnecting MongoDB. Health count/read operations have bounded timeouts. Configured dependencies with unavailable queues or unverified/stale workers make readiness DEGRADED; unconfigured optional dependencies remain explicitly NOT_CONFIGURED. The readiness endpoint retains its existing HTTP 200 envelope; deployment probes should inspect the status field.

Run `npm --workspace backend run campaign:worker` and `npm --workspace backend run api-campaign:worker` (or each command from backend). Existing queue names/job IDs/concurrency/retry semantics are unchanged. Restart already-running workers after deploying the heartbeat code; old workers cannot publish the new leases.

V2 health checked MongoDB, Redis/rate-limit configuration and Broadcast counts but had no durable worker heartbeat/API queue health. This adds requested operational hardening. Health is deployment-wide, not a per-tenant jobs endpoint; only aggregates are exposed. A role lease shows a recent process, not processing throughput or all replica identities. Multi-replica observability/alerts, backlog thresholds, Auth for operational visibility, and detecting hung individual jobs remain production work. Tests use fake Redis/queues, never live workers or business data.
